    Metrics and tracing

    Prometheus metrics on the admin listener, and OpenTelemetry traces that continue the caller's W3C trace context.

    Prometheus metrics

    Served at GET /metrics on the admin listener (:9090).

    MetricLabelsMeaning
    jwksbridge_snapshot_age_secondskeysetSeconds since the source last confirmed the keyset.
    jwksbridge_refresh_totalkeyset, resultRefreshes: updated, unchanged, error, invalid.
    jwksbridge_keyskeyset, statusKeys in the served snapshot per status.
    jwksbridge_requests_totalendpoint, codeRequests to jwks and keyset.
    jwksbridge_request_duration_secondsendpointRequest latency histogram.
    jwksbridge_source_errors_totalsourceErrors returned by Vault or the file source.
    jwksbridge_build_infoversion, commitAlways 1.

    Go runtime and process metrics are included.

    Suggested alerts

    - alert: JwksBridgeKeysetStale
  expr: max by (keyset) (jwksbridge_snapshot_age_seconds) > 1800
- alert: JwksBridgeRefreshFailing
  expr: sum by (keyset) (rate(jwksbridge_refresh_total{result=~"error|invalid"}[5m])) > 0
  for: 5m
- alert: JwksBridgeNoActiveKey
  expr: max by (keyset) (jwksbridge_keys{status="active"}) == 0
- alert: JwksBridgeKeysetErrors
  expr: sum(rate(jwksbridge_requests_total{endpoint="keyset",code!~"2..|304"}[5m])) > 0

    W3C trace context

    Every request on the public and private listeners extracts the traceparent and baggage headers, so a span started by Kong's opentelemetry plugin continues in the bridge. Calls to Vault carry the trace context on, and each background refresh is a keyset.refresh span with the Vault request as a child.

    Spans are exported only when an exporter is configured with the standard OpenTelemetry variables:

    OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector.observability:4318
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf     # or grpc
OTEL_TRACES_SAMPLER=parentbased_traceidratio
OTEL_TRACES_SAMPLER_ARG=0.1
OTEL_SERVICE_NAME=jwks-bridge

    Without them, propagation still works and nothing is exported. With JWKSB_LOG_LEVEL=debug, access log lines include trace_id and span_id.
