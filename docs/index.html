jwks-bridge

Sign tokens with a key stored in HashiCorp Vault on every Kong data plane, and publish the public JWKS through Kong for your backends.

Get started Documentation

Free and MIT licensed. For the Kong Gateway Enterprise jwt-signer plugin, in hybrid mode or Konnect.

Install

With Homebrew, the container image ghcr.io/bcollard/jwks-bridge, or the Helm chart oci://ghcr.io/bcollard/charts/jwks-bridge.

$ brew tap bcollard/jwks-bridge
$ brew install --cask jwks-bridge

Two documents from one Vault secret

Data planes load the private keyset directly from the bridge. Backends fetch the public JWKS through a Kong Route.

Vault KV v2secret/jwks-bridge/default
Keyset for jwt-signerhttps://jwks-bridge:8443/keyset
Public JWKShttps://kong/.well-known/jwks.json
Metricshttp://jwks-bridge:9090/metrics

Hybrid mode and Konnect

Every data plane signs with the same key, without a database on the data plane.

Staged rotation

Stage, promote, retire, remove. Verified end to end with no failed verification under load.

Survives Vault outages

In-memory snapshots keep serving the last good keyset; readiness reports staleness.

Private keys stay private

Separate TLS listener, mTLS or Basic auth, strict validation of every Vault write.

Metrics and tracing

Prometheus metrics, and OpenTelemetry spans that continue the W3C trace context from Kong to Vault.

Helm chart

Replicas, PodDisruptionBudget, NetworkPolicy, ServiceMonitor and a hardened distroless image.
